# Cloud Dungeon 客户端

Godot 4.6.1，当前游戏版本0.0.8、联机协议11。该目录是独立的客户端源码，可单独作为GitHub仓库根目录；不需要完整私有工程才能导入或构建。

使用Godot 4.6.1打开`project.godot`，等待资源导入后按F5。正式入口是主菜单，包含对战、对战记录、捐献、改动、日志、设置及关于。捐献入口先显示自愿支付说明，再由玩家自行前往爱发电。地图投稿和秘卷投稿入口均暂时关闭，原场景、功能和数据保留，方便以后恢复。日志装备预览可离线播放；对战需要兼容的服务器。

`assets/network/server.json`保存客户端连接地址，默认连接当前游戏服务器。地址和端口是公开客户端配置，不是管理凭证。自行测试时改为自己的服务器；避免用生产服务器运行自动化测试。服务器必须同时匹配游戏版本和协议版本。

选装可“跳过本次选择”并保留金币。对战记录提供本机／服务器页签；服务器页查看所有玩家最近100局已结束战斗，需要支持此功能的服务器。本机记录继续支持离线查看。

客户端只发送操作意图，应用服务器快照并播放动画；服务器决定实际对局结果。本仓库不包含服务器启动入口、匹配管理、权威对局编排、随机市场生成、地图供应／坍塌调度或投稿的服务端持久化实现。网络脚本中的服务端请求接收方法为空体，保留声明以兼容Godot RPC校验，不具备开服功能。

本仓库保留供日志动画、物品说明、目标选择及特效使用的共用规则，包括伤害、附魔和药剂的部分计算；这些代码也属于公开内容。详细边界见[客户端与私有服务端边界](docs/client_boundary.md)。

## 构建

已提供Android及Windows Desktop导出预设，输出到`build/`。安装Godot 4.6.1对应导出模板；Android另需本机配置JDK、Android SDK及自己的签名信息。签名密码在本机编辑器中配置，不提交仓库。该目录不附带APK、运行库或密钥。

保留`.gd.uid`、场景、资源、字体许可证及第三方署名。`.godot/`是本机缓存，已忽略。后续源码修改可以直接在该独立目录进行；从私有工程重新整理时应生成到新目录，避免覆盖这里的修改。

`tools/menu/`只附带客户端日志检查，可在Godot中运行`verify_journal.tscn`或`verify_glyph_previews.tscn`。检查关闭生产地址，不创建真实对局；输出写入忽略的`.godot/`。
