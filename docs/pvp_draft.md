# PvP 战前物资市场

联机双方到齐后，服务器随机分配先手、后手，生成双方共享的 6×6 共 36 项物资。
先手和后手均为 500 金币。

2026-10-26最新源码：五类装备各3格，剩余21格从药剂／卷轴／种子／符石合并池等概率、不放回抽取。
保留先手首次20秒／后续15秒、按类别分组、近战／投掷／护甲独立30%附魔／刻印。
本轮市场44,605断言、真实界面及11图／256种子地图规则验证PASS，日志见`.godot/pvp-runtime/market-layout/`，

本次尚未重建服务器归档或APK，未部署VPS；下文旧专项的构建记录按其日期理解。

匹配成功进入选装时，先播放约2秒的对阵介绍：对手名字从左侧进入屏幕中上方，
自己的名字从右侧进入中下方，居中显示 `vs`；双方名字各配全屏宽、65%不透明度的黑色横条。
停留后先隐藏 `vs`，对手向右切出，自己向左切出。姓名按真实座位映射，完整显示并自适应长名字，横竖屏横条均铺满视口。
随后双方金币数字从0在4秒内增长至预设金额（当前500），约每75ms播放一次原版 `gold.mp3`，
服从现有音量／静音设置，完成或退出即停止。每场仅播放一次，计时快照不会重播。
动画只改变显示数值，实际预算仍由服务器掌管。服务器禁止入场期间购买；
约6秒入场结束后才开始先手首个完整20秒购买机会，不占用选购时间。

每次购买整项物资，按显示价格一次扣款并获得图示数量。已购物资不会补货，原格留空，
避免其他选项移动导致误点。普通点击购买；长按或右键打开物品说明，有日志动画的8类物品
直接复用日志的正文＋预览窗口。戒指暂无日志动画，仍显示原纯说明窗口。
预览不提供装备、使用、放下或投掷操作。

2026-10-23已接入购买阶段动画：使用商店物品的副本，保留当前+0～+2等级、数量及实际数值，
展示规则只作用于独立本地世界，不改商品、已购装备或金币。长按松手不误购；窗口遮挡鼠标购买，

返回图标、点外侧、Esc或Android返回只关闭预览；换物品、查看地图、隐藏市场、离开购买阶段、
进入战斗或离开场景会取消并释放动画、在途投掷和规则世界。自己的／对方已购清单查看也走同一入口。

购买顺序是 **先手 → 后手 → 后手 → 先手**，然后重复。
先手第一次购买机会限时 **20 秒**，其余购买机会均为 **15 秒**。成功购买后下一次机会重新计时，包括同一人连续购买。
超时不扣金币、不发放物资，直接转给对方的下一个购买机会；
如果对方已买不起任何物品，仍按下述跳过规则由有购买能力的一方继续。
当一方无法负担任何剩余物资时，服务器自动跳过该方，由另一方继续购买。
当双方都买不起任何剩余物资，或者 36 项全部售出时，服务器自动进入战斗。
购买阶段不使用旧的十轮限制、所有回合统一20秒、秘密选择或竞标。

## 界面

- 屏幕中心固定排列 6×6 个物资格，每格采用 Claude 橙色按钮，下面显示整项售价。
- 物品图像、药水／卷轴类型角标、投掷武器／道具数量、装备升级数字直接复用背包 `InventorySlot` 和 `SpdPixelText`。
- 最上方展示对方名字、余额和公开已购清单；最下方展示自己的名字、先后手、余额和已购清单。
- 当前购买玩家右上角显示放大的原版红色像素数字，先手首次从20开始，其余从15开始倒数；每秒交替播放滴／答声，偶数秒为滴、奇数秒为答。退出购买阶段或轮到对方时停止，遵循音效音量／静音设置。
- 状态行右侧、退出按钮左侧增加探地卷轴图标的地图按钮，选装入场结束后可随时打开本局战斗地图，己方／对方购买回合都可使用。地图使用同一公开地形和区域风格；“返回选购”或Esc只关闭地图，不离开对局。地图遮挡期间不能误买背后的商品，购买倒计时继续，超时照常交给对方；进入战斗自动关闭地图。
- 两条已购清单可左右拖动；拖动不会触发物品点击或长按。点击清单物品也可以查看说明。
- 界面按安全区域整体缩放，保持六行六列；支持 360×640 和 320×568 竖屏布局。
- 只有当前购买方能够购买付得起且未被买走的物资；对方回合仍可以查看物品详情。

## 生成和定价

市场固定提供近战武器、投掷武器、护甲、法杖、戒指每类随机3种，共15格。
剩余21格从药剂（含合剂）、卷轴、种子和符石的全部合规类型中等概率、不放回抽取，各类实际数量随局变化，
不再分别固定4格。整局仍为36个不同类型，由服务器按近战→投掷→护甲→法杖→戒指→药剂→卷轴→种子→符石分组排列。
买走后原格留空、其他商品不移动。法师初始魔杖、任务镐不作为普通商品生成。

盛怒卷轴、祛邪卷轴、敌意符石、探魔符石和感知符石；
嬗变的随机结果也使用同一排除名单。市场始终为五类装备各3项加21项其他道具，共36项。

## 权威接口

`PvpEquipmentDraft.start(seed, with_intro, excluded_offer_types=[])` 创建市场；`buy(player, option, expected_turn)` 购买。
第三个参数为本场地图额外排除的商品类型，未传入时使用通常选购池，市场重开时重置；升级卷轴属于固定的市场排除，不受第三个参数重置影响。
正常联机的 `PvpAuthoritativeMatch.start()` 默认启用入场；直接测试市场规则时可关闭入场，避免不必要等待。
`advance(delta)` 检查服务器单调时钟的截止时间，按秒通知状态更新，超时发出 `timed_out(player)` 并推进购买回合票据；`buy` 同样检查截止时间，拒绝迟到请求。
这里的 player 0 表示先手，1 表示后手，与连接 seat 无关。
`state_for(player)` 返回余额、价格、格子归属、购买回合、剩余毫秒和双方公开已购清单。
另含入场剩余时间、名字／发钱阶段时长和双方初始预算，客户端据此呈现同步动画。
相关实现为 `scripts/ui/draft_match_intro.gd` 与 `scripts/pvp/client/market_view.gd`；
离线验证为 `tools/pvp/verify_draft_intro.tscn`，截图／日志在 `.godot/pvp-runtime/draft-intro-check/`。
`purchased` 通知一次成功交易，`completed` 通知自动进入战斗。

客户端只发送 `buy` 意图、格子编号和当前购买回合票据；服务器验证对局、身份、回合、
库存、余额和截止时间，再扣款发放。价格和金币字段即使被客户端伪造也不会参与结算。
网络请求序号和购买回合票据共同避免重复扣款，包括后手连续两次购买的情况。

网络协议当前为11（默认 ENet/UDP，保留压缩状态快照及独立心跳／操作通道）。2026-10-26的首手20秒、市场分类排列与30%附魔改动均由服务器控制，需部署更新后的服务器才会生效；快照格式和RPC未变，现有协议11客户端可显示新倒计时、排序和附魔，无需仅为本次规则改动重装客户端。此处记录源码行为，既有0.0.7服务器归档未重建，未部署VPS。
早期单机选装演示已移除；正式联机选装、服务器规则和回归验证保留。
